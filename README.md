# Scene It

Flick through the 10,000 most-voted movies and the 5,000 most-voted TV
shows on IMDb, one at a time. Seen it or not? Rate it if you like. Export
the list for Letterboxd, Trakt, Simkl, a spreadsheet, or the Piddicus Watch
List.

Plain HTML, CSS and JavaScript. No build step, no server, no API calls from
the page. Title data is static JSON generated by the scripts below; posters
are shown straight from TMDB's and IMDb's image hosts.

```
index.html           The page
app.js               Deck, list, export, import
style.css            Styles (Piddicus site tokens, with a built-in fallback)
data/
  movies.json        The movie list (about 1.5 MB): id, title, year, runtime,
                     genres, IMDb rating and votes, directors, cast
  shows.json         The TV list (about 0.9 MB): the same plus end year,
                     seasons and episodes
  movies/<n>.json    Synopsis and poster URL per movie, 200 per file, loaded
  shows/<n>.json     on demand by the deck
project.json         Card metadata for the Piddicus menu
preview.svg          Card illustration for the Piddicus menu (320x200)
scripts/
  build-data.py      Builds data/movies.json or data/shows.json from the IMDb datasets
  fetch-tmdb.py      Fetches synopses and posters from TMDB (free key)
  fetch-details.py   Builds the data/movies and data/shows chunk files
  collect-*.{py,js}  Optional: IMDb's own plot outlines, collected in a browser
```

## Using it

**Movies, TV shows, or both.** The switch next to the tabs picks which list
the deck, the table, the progress bar and every export work from (keys M, T
and B). Answers are kept by IMDb id, so switching never loses anything.

**Deck.** One title per card: poster, title, year (or years, seasons and
episodes for a show), runtime, director, cast, genres, IMDb rating, a short
synopsis, and a link to the IMDb page. Four answers: seen, not seen, want
to watch, skip for now. The first three count as decided and the title
leaves the deck; skipped ones come back at the end. Click the rating bar
(half-point steps) or press a digit to mark it seen with a rating. Swipe on
touch screens. Undo with Z.

| Key | Action |
| --- | --- |
| `→` `S` `Enter` | Seen it |
| `←` `N` `X` | Haven't seen it |
| `↑` `W` | Want to watch |
| `1`…`9`, `0` | Seen it, rated 1 to 10 (0 is 10) |
| `↓` `Space` `K` | Skip for now |
| `Z` `Backspace` | Undo |
| `M` `T` `B` | Movies, TV shows, both |
| `/` | Search |
| `?` | Shortcuts |

Skipped movies come back at the end of the queue. The filters (order,
decade, genre, minimum IMDb rating in half steps, search over titles,
directors and cast) shape the queue.

**List.** Every movie in a scrolling table with the same answers, for
finding a specific title or fixing a mistake.

**Export.**

Every export follows the Movies / TV shows / Both switch, and a scope: the
seen list, the want-to-watch list, everything decided, or everything
including skips. The three list formats take one list at a time (seen, or
want to watch), because that is how those sites import; the data formats
take any scope.

| Format | For | Shows |
| --- | --- | --- |
| Piddicus Watch List | `watched.txt` on piddicus.com (`# show` and `# movie` sections, `Title \| rating` lines; want-to-watch titles are written as `Title \| \| want to watch`). On the site there is also an "Open in the Watch List" button. | Yes |
| Letterboxd CSV | letterboxd.com/import, as watched films or, with the want-to-watch scope, as a watchlist (`imdbID, Title, Year, Directors, Rating10`) | No: Letterboxd has no TV import, so shows are left out and the page says so |
| IMDb CSV | The layouts IMDb itself exports: ratings for the seen list, list/watchlist for want to watch. Accepted by Trakt (Settings, Data, Import), Simkl (Apps, Import), TMDB and others | Yes, with `Title Type` set to `TV Series` |
| Plain CSV | Spreadsheets. A `status` column carries seen, unseen, want or skip. | Yes, with `type`, `end_year`, `seasons`, `episodes` columns |
| JSON backup | Load back in here to restore progress | Yes |
| Text list, Markdown checklist | Paste anywhere | Yes, in separate sections when both are exported |

**Import.** A JSON backup restores everything. A Letterboxd export
(`watched.csv`, `ratings.csv` or `diary.csv`), an IMDb ratings CSV, or a
Piddicus watch list marks those titles as seen; a Letterboxd
`watchlist.csv`, an IMDb list export, or Piddicus lines noted "want to
watch" mark them as want to watch. Matching is by IMDb id when the file has
one, otherwise by title and year, narrowed to shows or movies when the file
says which (a `Title Type` column, or `# show` / `# movie` lines in a
Piddicus list).

**Where answers live.** In the browser's localStorage, per browser and per
device. They survive reloads and browser restarts, and go away if the
visitor clears site data or uses a private window. Nothing is sent
anywhere. To move progress to another device, export a JSON backup and
import it there.

## Building the data

Both steps run on your machine, once, and need no account or key.

**1. Titles, from the IMDb datasets** (plain downloadable files, personal
non-commercial use allowed; nothing here touches imdb.com itself):

```bash
mkdir imdb && cd imdb
curl -O https://datasets.imdbws.com/title.basics.tsv.gz
curl -O https://datasets.imdbws.com/title.ratings.tsv.gz
curl -O https://datasets.imdbws.com/title.crew.tsv.gz
curl -O https://datasets.imdbws.com/title.principals.tsv.gz
curl -O https://datasets.imdbws.com/title.episode.tsv.gz
curl -O https://datasets.imdbws.com/name.basics.tsv.gz
cd ..
python scripts/build-data.py --source imdb --kind movie
python scripts/build-data.py --source imdb --kind show
```

Movies are feature films only (no TV movies, shorts or adult titles), with
up to three directors and four top-billed actors each. Shows are TV series
and mini-series with cast, end year, and season and episode counts from
`title.episode`. Both are ordered by vote count; `--top` sets how many to
keep (default 10,000 movies, 5,000 shows). Each run takes about ten
minutes; `title.principals` is the slow one.

**2. Synopses and posters.** Two sources, either or both:

*TMDB* (recommended: complete, five minutes). Make a free account at
themoviedb.org, request an API key under Settings, API, save it to
`scripts/.cache/tmdb-key.txt`, then:

```bash
python scripts/fetch-tmdb.py --movies data/movies.json
python scripts/fetch-tmdb.py --movies data/shows.json
```

*IMDb's own plot outline*, if you prefer its wording. Each IMDb title page
carries the outline and poster as structured data, but the pages only load
in a real browser and IMDb rate-limits, then blocks, sessions that fetch
quickly (a CloudFront block lasts an hour or so). Optional, and slow: it
runs in your browser, one page at a time:

```bash
python scripts/collect-server.py
```

Leave that running, open any imdb.com title page in your browser, open the
developer console (F12), paste the contents of `scripts/collect-imdb.js`
and press Enter. It fetches the remaining title pages from inside that tab
(reading only the first few tens of KB of each), and posts the results to
the local server, which writes `scripts/.cache/imdb-plots.jsonl`. One page
at a time with a pause, and a two-minute wait whenever IMDb answers 403:
count on several hours for all 10,000. `window.__collect` in the console
shows progress; if the tab is closed, paste again and it resumes from the
cache. Stop the server with Ctrl-C when `__collect.running` is false.

**3. Build the details files:**

```bash
python scripts/fetch-details.py --movies data/movies.json
python scripts/fetch-details.py --movies data/shows.json
```

Per title this takes the IMDb plot outline if collected, else the TMDB
overview, else a trimmed Wikipedia summary; and the IMDb poster if
collected, else TMDB's. The page links to a 300px-wide copy of each poster
on the source's image host rather than storing images. All caches live in
`scripts/.cache/`, so reruns are quick, and no step makes requests to
imdb.com.

## Putting it on piddicus.com

Push this folder to a GitHub repository, then in the site checkout:

```bash
npm run sync -- https://github.com/ProgrammingPaddy/<repo-name>
```

The sync copies the files into `public/projects/<repo-name>/`, records the
commit in that folder's `project.json`, and rebuilds the menu. Copy
`preview.svg` to `public/previews/<repo-name>.svg` by hand once (the sync
does not touch `public/previews`). Commit and push the site. Later,
`npm run sync -- <repo-name>` pulls the latest commit.

For a local look, `.claude/launch.json` has a `standalone` server on port
8791 (this folder, no site chrome) and a `site` server on 8790 that serves
`../piddicuscom/public` once the project has been synced there.
